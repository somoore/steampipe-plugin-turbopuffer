## Residual risk

1. **`govulncheck` is not a CI gate (F-19).** Vulnerability detection relies on GitHub's dependency graph (fed by `dependency-submission.yml`) and Dependabot alerts. If a future advisory lands in a *reachable* symbol, CI will not fail; it will surface as an alert.
2. **Dependabot auto-merge still exists (F-04/F-18).** Cooldown shrinks but does not remove the window for a malicious upstream patch release; `make test` cannot detect malicious code. A human review requirement would close it but breaks the solo-maintainer workflow.
3. **Region validation is a charset check, not an allow-list (F-05).** A new region on a different naming scheme would be dropped (with a warning) rather than used; the matrix would silently narrow until the pattern is extended. This is deliberate: an allow-list would break the day turbopuffer launches a region.
4. **Vector redaction is type-driven (F-06).** Types that are structurally vectors but do not end in `f16/f32/f64/bf16` are not stripped. The SDK's documented type list contains no such type today; the server-side `exclude_attributes` approach would remove the local-predicate dependency entirely and is the recommended follow-up.
5. **Recall caps are policy constants (F-07).** Legitimate workloads needing more than 1000 evaluation searches now get an error; they can be raised deliberately, but no such need was evidenced.
6. **Not fixed / not verified:** live turbopuffer confirmation of the sparse-vector leak and the region redirect (no credentials used, per policy) — both are unit/probe-proven. The `steampipe` CLI end-to-end path remains unverified (QA's harness hung). Local dev secret scanning still degrades to a warning without `CI=true`.
